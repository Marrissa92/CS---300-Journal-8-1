### Course Project Portfolio Reflection

* **What was the problem you were solving in the projects for this course?**
In the projects for this course, I solved a core data management problem for an academic advising system. The goal was to build a system that could efficiently read an external data file, load the courses into memory, validate that all listed prerequisites actually exist, sort the catalog alphanumerically, and allow advisors to instantly look up individual course details.
* **How did you approach the problem? Consider why data structures are important to understand.**
I approached this problem by giving equal design treatment to three distinct architectures: Vectors, Chained Hash Tables, and Binary Search Trees (BST). To make a fair comparison, I analyzed the exact sorting algorithms required for each model to display an alphabetical list. For the Vector, I designed a standard Bubble Sort loop to actively swap adjacent elements. For the Hash Table, since data is scattered randomly by key indexes, I implemented an extraction step to pull data into a temporary array before running that same Bubble Sort routine. For the BST, I utilized a native In-Order Traversal to print sorted data automatically. Understanding data structures is vital because this comparison proved that selecting the right framework directly dictates whether your program relies on heavy quadratic \(O(n^2)\) sorting loops or clean, highly efficient linear \(O(n)\) processes to meet user requirements.
* **How did you overcome any roadblocks you encountered while going through the activities or project?**
I hit several distinct roadblocks, including file stream parsing errors where trailing empty columns were misread as blank prerequisites, hidden Windows carriage returns (\r) breaking code matching rules, and lingering IDE file locks that caused build permission errors. I overcame these issues by adding a data cleaning step to filter out empty spaces and carriage returns before nodes are built, and by using the project clean/restart routines in Eclipse to safely break background application locks during compilation checks.
* **How has your work on this project expanded your approach to designing software and developing programs?**
This project has completely shifted my mindset from just writing code that works to consciously planning how a program executes behind the scenes. I now look at software design through the lens of algorithmic efficiency, meaning I map out data relationships, input boundaries, and potential worst-case performance scenarios on paper before writing a single line of actual code.
* **How has your work on this project evolved the way you write programs that are maintainable, readable, and adaptable?**
My work has reinforced the value of clean, modular coding architectures. By separating my tree operations, native string parsing loops, and user menu logic into clear, independent blocks inside a single standalone file, the code remains highly readable and easy to navigate. This design makes the program exceptionally adaptable; if the underlying data format changes or if a new sorting method needs to be implemented in the future, the structural components can be updated cleanly without breaking the rest of the application.
